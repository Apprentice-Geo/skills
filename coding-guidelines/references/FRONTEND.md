# 前端开发与验证准则

适用于 Web 前端、桌面应用 UI 及其它基于浏览器渲染技术的界面开发。遵循 [coding-guidelines](../SKILL.md) 的通用约束，本文件仅补充前端特有的规则。

## 界面开发

- 根据产品定位、内容和使用场景进行有目的的视觉设计，合理发挥创造力，避免缺乏设计意图的模板化布局、装饰和动画。
- 新界面允许主动探索排版、色彩、层次和动效；修改已有界面时，优先遵循项目的设计系统、组件和交互模式，避免无关的风格变更。
- 视觉元素应服务于内容表达、信息层次或交互反馈。允许有辨识度的设计，但不为视觉丰富度而增加不必要的复杂度。
- 根据目标平台、实际使用场景和已有项目约定决定布局适配范围，不默认要求支持所有视口、内容长度和界面状态。
- 对明确的布局、对齐、间距和尺寸关系，优先使用布局约束表达，避免依赖脆弱的绝对坐标。

## 验证范围

遵循主文档的测试质量与验证停止规则，按本次需求和缺陷选择检查对象，不将任何单一验证手段视为所有前端任务的必经步骤。

- **功能行为**：根据实际风险选择单元测试、组件测试或端到端交互测试，验证重要的状态变化和用户可观察行为。
- **布局关系**：仅当布局关系属于明确需求、已有有效契约或本次缺陷的复现条件时，才检查对应的 DOM、计算样式或几何约束。不为普通样式调整逐项断言坐标、尺寸、间距或计算样式，也不默认将一次性排查转为永久测试。
- **响应式布局**：仅针对项目明确支持的视口和布局模式进行必要验证，不默认遍历多种窗口尺寸或进行多视口截图检查。
- **像素比较**：默认不新增截图像素比较、图像差异阈值或其它像素级视觉回归测试；用户明确要求像素还原，或项目已有适用的视觉回归契约时，按该要求验证。

几何检查优先验证所需的相对关系，并考虑必要的浮点误差和布局容差。不把浏览器渲染细节、字体抗锯齿或无明确要求的微小视觉差异变成测试契约。

## 截图使用

截图用于补充视觉证据，不是默认验证步骤。

- 不在每次代码修改、样式调整或交互操作后自动截图。
- 将一组相关界面修改完成后，再按需集中检查。截图用于整体呈现检查、具体视觉缺陷定位或用户要求的视觉对照，不替代可以直接完成的行为验证。
- 每次截图应对应具体检查对象和相关界面状态；再次截图应针对尚未解决的问题，或验证相关修复。已有证据充分时，不重复采集或查看。
- 不默认保存或提交截图产物。

## 视觉与动画验收

- Agent 可以通过有限的渲染检查发现明显的布局、可见性和呈现问题；主观审美及动画连续观感不由静态检查证明。
- 动画自动化测试仅检查与本次需求或缺陷相关的关键状态、布局及明确要求的时间行为；需要检查中间状态时，可以控制动画时间或播放状态，使测试具有确定性。
- 不通过频繁截图尝试重建、分析或评价完整动画效果，也不将静态截图通过等同于动画连续性、缓动、节奏或流畅性通过。
- 仅在要求人工验收，或仍有具体无法确认的问题时，列出待验收项，不为每次前端修改附加笼统的人工验收要求。
- 汇报时区分已检查的行为与呈现、主观判断及未确认的问题，不将未执行的检查或人工验收报告为已通过。
