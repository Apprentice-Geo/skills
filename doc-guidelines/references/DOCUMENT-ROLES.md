# 文档职责参考

本文说明如何按读者和内容职责选择文档位置。三类文档的定义见 [文档类型](<../SKILL.md#文档类型>)。所有文件和目录均按需创建，以下名称仅作推荐，也可以使用其它名称或增加专题文档。

## 常驻文档

### README.md

- **读者**：项目用户及初次接触项目的人。
- **职责**：介绍项目用途，帮助读者理解、获取和使用项目。
- **适合内容**：项目简介、目标与主要特性，安装、配置、快速入门、基本使用示例，用户需要了解的限制，以及其它文档入口。

可以包含安装、配置和运行所必需的技术命令；内部架构和完整开发规范应由对应文档维护。

### AGENTS.md

- **读者**：人类开发者与 Coding Agent。
- **职责**：提供理解、修改、运行和验证项目代码所需的开发指引。
- **适合内容**：开发环境与依赖要求，构建、运行、测试和验证命令，代码风格、格式化与 Lint 要求，开发约束、关键目录与模块入口，以及其它开发文档索引。

保持准确、可操作且适当精简。某类知识已由独立文档维护时，保留摘要和引用。

### ARCHITECTURE.md

- **读者**：需要理解系统内部设计的开发者。
- **职责**：描述相对稳定的架构、模块关系和关键设计。
- **适合内容**：整体架构、主要组件、模块职责、代码地图、重要数据流与控制流、关键接口、模块依赖，以及当前有效的重要技术设计。

架构内容较少时，可以在开发指引中维护必要概述；大型或复杂项目可以拆分模块级架构文档，并从全局文档提供索引。

### CONTRIBUTING.md

- **读者**：准备参与开发的外部贡献者。
- **职责**：说明如何参与项目及其协作约定。
- **适合内容**：贡献方式、Issue 和 Pull Request 要求，分支、Commit、代码审查约定，贡献前的检查及社区沟通方式。

具体开发命令和技术规范引用对应开发文档。贡献约定较少时，可以在项目介绍中简要说明。

### UI_UX.md

- **读者**：UI 开发者、设计师与 Coding Agent。
- **职责**：维护当前有效的视觉设计语言和用户体验约定。
- **适合内容**：视觉风格、色彩、字体、排版、间距、布局、视觉层级、常见组件设计规范、交互反馈、动效、响应式布局及可访问性要求。

组件实现、状态管理等内部技术设计属于架构职责。只有少量简单 UI 约束时，可以在开发指引中维护。

### 其它专题或模块文档

API 参考、部署指南、运维手册及模块文档等，按实际读者和独立维护需要设置；从相关入口提供引用，无需将其内容集中复制到上述文件。

## 工作文档与归档文档

### 工作文档

适合记录复杂功能计划、重构或迁移方案、阶段性设计探索、开发进度、未解决问题、后续步骤，以及跨会话或开发者的上下文交接。

当前任务的状态、待办事项和实现思路放在工作文档中；已经成为项目长期约束或当前设计的内容，应由相应常驻文档维护。

### 归档文档

适合保留已结束或终止的工作计划、历史技术决策、设计探索及值得保留的问题和经验。

工作文档的维护及归档文档的读取、核实和保留规则统一见 [文档组织准则](<../SKILL.md>)。
