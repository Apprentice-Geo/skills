# article-format-correction

## 范围与优先级

校对中英文 Markdown 技术文章时，以用户指定的范围为准。默认只修正明确错误，并应用下文格式规范；翻译、总结、扩写和重组文章不属于校对。

保留原意、技术结论、章节和讲解顺序、段落边界，以及作者的语气、措辞和确信程度。个人笔记可以保留口语表达。校对时不补写事实、示例、解释、结论或背景。

## 错误修正

仅修正明确的错误：

- 错别字、重复字符、明显的语法错误，以及缺失或错误的标点。
- 当预期 Markdown 格式明确时，修正格式错误的标题、列表、表格、链接、图片或围栏代码块。
- 修正公式标记错误，以及上下文明确应使用 LaTeX 却未标记的数学表达式。

## 格式规范

除非用户另有指定，校对时默认应用下列排版与标记规范：

- **空格**：中英文之间、中文与数字之间、数字与单位之间加空格；全角标点与其他字符之间不加空格。
- **中文标点与引号偏好**：中文句子使用全角中文标点，但其中的英文整句或特定英文专名内部使用半角标点；中文句子使用 `「」`、`『』`、`[]` 和半角空格，不使用 `“”`、`‘’`、`【】` 和全角空格。
- **专有名词与缩写**：专有名词使用正确大小写（例如 GitHub、Google、ChatGPT）；不使用不地道的缩写（例如 TypeScript 不写作 Ts，HTML5 不写作 h5）。
- **Markdown 链接**：所有链接目标、图片目标和引用定义均使用尖括号包围，例如 `[示例](<https://example.com>)`。

例外情况：

- 度数、百分比与数字之间不加空格，例如 `90°`、`15%`。
- 中文句子内出现英文书名或报刊名时，不使用中文书名号，改用斜体标记，例如 `*Nature*`。

## 公式与代码

- 保持现有有效 LaTeX 不变。
- 短行内公式使用 `$...$`，较长或较大的独立公式使用 `$$...$$`；`$` 与公式内容之间禁止添加空格。
- 保留变量、记号和数学含义。不得推导、简化或重新解释公式或代码。
- 仅当上下文明确用于定义数学量或表达数学关系时，将未标记的数学表达式改写为 LaTeX，例如动态规划递推式、变量范围、求和、乘积和集合运算。不能仅凭赋值、运算符或变量名判断其为公式。
- 行内代码或未标明语言的围栏代码块，仅在上下文明确其为误用代码格式的数学公式时转换。程序片段、带语言标记的代码块和用途不明确的赋值保留原样；有歧义时不转换。公式中的标识符包含下划线时，将其保留为文本：`$N = \text{duration\_samples}$`。
- 短行内代码使用 `` `...` ``；真正的独立代码使用带正确语言标记的围栏代码块。

示例：

| 修改前 | 修改后 | 规则 |
| --- | --- | --- |
| `时间复杂度为 O(n log n)` | `时间复杂度为 $O(n \log n)$` | 将未标记的数学表达式改写为 LaTeX。 |
| `统计满足 x*y=k 的 x，y 数量` | `统计满足 $x \times y = k$ 的 $x$，$y$ 数量` | 只转换公式和变量；若计数对象（例如是有序对还是无序对）有歧义，在「需确认项」中提示作者。 |
| `n、in【1，2e5】` | `$n \in [1,2 \times 10^5]$` | 将数学表达式改写为 LaTeX。 |
| `递推公式为 dpi=dpi-1+dpi-2，i>=2` | `递推公式为 $dp_i = dp_{i-1} + dp_{i-2}, i \ge 2$` | 将递推式改写为 LaTeX。 |
| `定义总采样数 N = duration_samples。` | `定义总采样数 $N = \text{duration\_samples}$。` | 上下文明确为数学定义时转换。 |
| `N = duration_samples` | `N = duration_samples` | 缺少上下文，无法区分数学定义与程序赋值，保留。 |
| `N ∈ dp[K][j]` | `$N \in dp[K][j]$` | 改写集合成员关系表达式，同时保留数组访问记法。 |
| `score = Σ loadᵢ²` | `$score = \sum_i load_i^2$` | 改写求和表达式，不臆造缺失的上下界。 |
| `zip（）返回一个包含一些元组的迭代器` | `` `zip()` 返回一个包含一些元组的迭代器 `` | 代码标识符使用行内代码格式。 |
| `[示例](./example image.png)` | `[示例](<./example image.png>)` | 使用尖括号包围链接目标。 |

对于较长或较大的公式，使用独立的展示块：

```markdown
$$
dp_i = \sum_{j=0}^{i-1} dp_j \times w_{j,i}, \quad i \ge 1
$$
```

## 受保护内容与不确定项

- 修正 Markdown 标记时，保留程序代码、命令、终端输出和日志的原文，包括代码的缩进和注释。
- 给链接目标加尖括号时保留路径和 URL 原文。校对表格时只修正有明确错误的标记或单元格文字，保留原有行列和分隔线结构。
- 保留版本号和项目专有名称。术语、命令、路径、版本、公式或技术陈述存疑时保留原文，记下疑点及原因。

## 一键确定性检查与最终验证

本 Skill 提供确定性格式检查脚本（只报告问题，不自动改写原文件），用于检查空格、全半角标点、引号偏好、链接尖括号、行内公式空格、专有名词大小写、围栏闭合和表格列数等可确定规则；是否属于数学公式、代码格式误用和受保护内容仍由 Agent 结合语义判断。

首次使用前，在 Windows 下从本 Skill 目录运行 `scripts\setup\setup_windows.bat` 配置 Python 3.12 环境（需要 `uv`）。校对文件前后可运行：

```powershell
uv run --no-sync python -m scripts.check_format "<markdown-file>"
```

- 退出码 `0` 表示无 error（可能仍有需人工判断的 warning）；`1` 表示存在确定性格式 error；`2` 表示参数或文件读取错误。
- 修改前运行一次作为基线，修改后再运行一次验收。若脚本报出的某条命中属于语义例外或受保护内容，不强行修改，在「需确认项」中说明原因。
- 除脚本检查外，通读改动处，核对同类对象格式是否一致，并对照原文核实技术含义、受保护内容和作者语气。

## 输出

如果编辑文件，更新原文件。如果用户直接粘贴文本，返回修正后的文本。

在「修改说明」中概括有意义的改动。有待核实的内容时，再列出「需确认项」及简要原因。
